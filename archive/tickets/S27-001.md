# S27-001: Define ViolationKind, ViolationMemory, and ViolationDispositionProfile in worldwake-core

**Status**: PENDING
**Priority**: HIGH
**Effort**: Medium
**Engine Changes**: Yes — new component types, component schema/tables registration, belief enum variant
**Deps**: None (S22, S23 already completed; this ticket has no intra-S27 deps)

## Problem

No types exist to represent detected belief-perception mismatches, to remember which violations an agent has already noticed (preventing goal thrashing), or to govern per-agent investigation behavior. These are prerequisites for all downstream S27 tickets.

## Assumption Reassessment (2026-03-25)

1. `SocialObservationKind` in `crates/worldwake-core/src/belief.rs` currently has 5 variants (`WitnessedCooperation`, `WitnessedConflict`, `WitnessedObligation`, `WitnessedTelling`, `CoPresence`). Adding `WitnessedAbsence` is a new 6th variant. Confirmed by grep.
2. Component registration in `component_schema.rs` uses `with_component_schema_entries()` to declare which `EntityKind` accepts which components. Agent-only components follow the pattern of `BlockedIntentMemory`, `IntentionFrame`, `UtilityProfile`, etc. Confirmed by file read.
3. Component tables in `component_tables.rs` use macro-generated typed storage. New components require entries in the macro invocation. Confirmed by file read.
4. `Permille` newtype exists in `crates/worldwake-core/src/numerics.rs` for [0,1000] range values. `NonZeroU32` is used for durations elsewhere (e.g., `IntentionDispositionProfile`). Both confirmed present.
5. No existing `violation.rs` module in worldwake-core. Confirmed by glob.

## Architecture Check

1. Follows the same pattern as `BlockedIntentMemory` (Vec with TTL-based retention and kind-based deduplication) and `TellProfile`/`IntentionDispositionProfile` (per-agent profile structs). No novel architectural patterns introduced.
2. No backwards-compatibility aliasing/shims introduced.

## Verification Layers

1. `ViolationMemory::record()` deduplicates by kind -> focused unit test
2. `ViolationMemory::expire()` removes entries past TTL -> focused unit test
3. `ViolationMemory::is_recorded()` returns false for expired entries -> focused unit test
4. `ViolationDispositionProfile` fields use `Permille` and `NonZeroU32` (no magic numbers) -> compile-time type enforcement + focused construction test
5. `SocialObservationKind::WitnessedAbsence` variant exists and is serializable -> serde round-trip unit test
6. Component registration accepts `ViolationMemory` and `ViolationDispositionProfile` on Agent entities -> focused schema test or compile-time enforcement via `component_schema.rs`
7. Single-layer ticket (core types only); additional layer mapping not applicable.

## What to Change

### 1. New module `crates/worldwake-core/src/violation.rs`

Define:
- `ViolationKind` enum with variants `EntityMissing { entity: EntityId, expected_place: EntityId }`, `SupplyDepleted { commodity: CommodityKind, source: EntityId, place: EntityId }`, `EntityDead { entity: EntityId }`. Derive `Clone, Debug, Eq, Ord, PartialEq, PartialOrd, Serialize, Deserialize`.
- `RecordedViolation` struct with fields `kind: ViolationKind`, `observed_tick: Tick`, `expires_tick: Tick`. Derive `Clone, Debug, Eq, PartialEq, Serialize, Deserialize`.
- `ViolationMemory` component struct with `violations: Vec<RecordedViolation>`. Derive `Clone, Debug, Default, Eq, PartialEq, Serialize, Deserialize`. Implement `Component` trait. Methods: `is_recorded(&self, kind: &ViolationKind, current_tick: Tick) -> bool`, `record(&mut self, kind: ViolationKind, observed_tick: Tick, ttl: u32)` (replaces existing entry for same kind), `expire(&mut self, current_tick: Tick)`.
- `ViolationDispositionProfile` struct with `investigation_duration_ticks: NonZeroU32`, `violation_memory_retention_ticks: u32`, `investigation_motive_weight: Permille`, `ownership_motive_bonus: Permille`. Derive `Clone, Debug, Eq, PartialEq, Serialize, Deserialize`. Implement `Component` trait.

### 2. Register in `crates/worldwake-core/src/lib.rs`

Add `pub mod violation;` and re-export public types.

### 3. Register components in `crates/worldwake-core/src/component_schema.rs`

Add `ViolationMemory` and `ViolationDispositionProfile` to the Agent entity kind's component list in `with_component_schema_entries()`.

### 4. Register in `crates/worldwake-core/src/component_tables.rs`

Add `ViolationMemory` and `ViolationDispositionProfile` to the macro-generated component table entries.

### 5. Add `SocialObservationKind::WitnessedAbsence` in `crates/worldwake-core/src/belief.rs`

New variant on the existing enum. No additional fields on the variant itself (the `SocialObservation` struct's `subjects` field carries `(missing_entity, place)`).

### 6. Forward through serialization boundary

Ensure `ViolationMemory` and `ViolationDispositionProfile` participate in `forward_authoritative_components()` and `select_txn_simple_set_components()` if required by the existing component forwarding pattern.

## Acceptance Criteria

### Tests That Must Pass

1. `ViolationMemory::record()` replaces existing entry for the same `ViolationKind` (deduplication by kind)
2. `ViolationMemory::is_recorded()` returns `true` for unexpired violation, `false` after TTL expires
3. `ViolationMemory::expire()` removes all entries where `current_tick >= expires_tick`
4. `ViolationKind` serde round-trip for all 3 variants (bincode serialization matches the project's deterministic storage)
5. `SocialObservationKind::WitnessedAbsence` variant exists and serializes correctly
6. `ViolationDispositionProfile` constructs with valid `NonZeroU32` and `Permille` fields
7. Existing suite: `cargo test -p worldwake-core`
8. Existing suite: `cargo clippy -p worldwake-core`

### Invariants

1. All `ViolationKind` derives include `Ord` + `PartialOrd` for deterministic `BTreeMap`/`BTreeSet` storage
2. No `HashMap`/`HashSet` used in any new types (determinism invariant)
3. No hardcoded numeric constants — all behavioral parameters come from `ViolationDispositionProfile` fields
4. `ViolationMemory` and `ViolationDispositionProfile` are Agent-only components (not registered for Place, ItemLot, etc.)
5. No floats (`f32`/`f64`) — `Permille` used for fractional values
