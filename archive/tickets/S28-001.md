# S28-001: Define knowledge path types (core + ai)

**Status**: ✅ COMPLETED
**Priority**: HIGH
**Effort**: Small
**Engine Changes**: Yes — new diagnostic types in worldwake-core and worldwake-ai
**Deps**: S21 (completed), S25 (completed)

## Problem

The decision trace system records the causal path through the AI pipeline but not the knowledge path — which specific beliefs motivated each goal candidate and how they were acquired. This ticket defines the type foundations for knowledge path tracing across two crates.

## Assumption Reassessment (2026-03-25)

1. `HomeostaticNeeds` exists at `crates/worldwake-core/src/needs.rs:8-15` with fields `hunger`, `thirst`, `fatigue`, `bladder`, `dirtiness` — all `Permille`. No `HomeostaticNeedId` enum exists yet.
2. `CandidateEvidenceTrace` exists at `crates/worldwake-ai/src/decision_trace.rs:292-296` with fields `goal: GoalKey`, `contributors: Vec<CandidateEvidenceContributor>`, `exclusions: Vec<CandidateEvidenceExclusion>`. No `knowledge_path` field exists.
3. `CandidateEvidenceKind` enum at `decision_trace.rs:259-265` has 5 variants: `Seller`, `LooseLot`, `ResourceSource`, `Corpse`, `RecipeWorkstation`. Missing `Listener`, `TellSubject`, `OfficeParticipant`.
4. `PerceptionSource` at `crates/worldwake-core/src/belief.rs:626-631` has variants: `DirectObservation`, `Report { from, chain_len }`, `Rumor { chain_len }`, `Inference`.
5. `InstitutionalKnowledgeSource` at `crates/worldwake-core/src/institutional.rs:172-182` has variants: `WitnessedEvent`, `Report { from, chain_len }`, `RecordConsultation { record, entry_id }`, `SelfDeclaration`.
6. `BelievedInstitutionalClaim` at `institutional.rs:164-169` has fields: `claim`, `source`, `learned_tick`, `learned_at: Option<EntityId>`.
7. No `knowledge_path.rs` module exists in worldwake-ai.
8. Single-layer ticket: only defines types and adds a `Default`-initialized field. No behavioral change.

## Architecture Check

1. Placing `HomeostaticNeedId` in worldwake-core next to `HomeostaticNeeds` is the natural home — it identifies a need field by name, used across crates. Placing diagnostic types (`BeliefProvenance`, `KnowledgePath`, etc.) in worldwake-ai is correct because they are AI-diagnostic-only and never part of authoritative state.
2. No backward-compatibility shims. The new `knowledge_path` field on `CandidateEvidenceTrace` uses `Default` so all existing construction sites remain unchanged.
