# S148PORMOTBAC-002: Lift PortfolioSlotWeights to PortfolioWeightsProfile universal component

**Status**: COMPLETED
**Priority**: HIGH
**Effort**: Large
**Engine Changes**: Yes — removes `PortfolioSlotWeights` from `CognitiveProfile`; introduces `PortfolioWeightsProfile` universal ECS component on `EntityKind::Agent`; threads weights read through a new `GoalBeliefView` accessor
**Deps**: `archive/tickets/S148PORMOTBAC-001.md`, `archive/specs/S148-portfolio-and-motive-backed-intentions.md`

## Problem

`PortfolioSlotWeights` currently lives as an embedded field on `CognitiveProfile` (`crates/worldwake-core/src/cognitive_profile.rs:5-19, 120`), conflating planning-search parameters (`max_node_expansions`, `switch_margin`, backoff caps) with portfolio-selection parameters (per-slot priority). The codebase already has 30+ universal `*Profile` components (MetabolismProfile, PerceptionProfile, RiskWeightProfile, LawAbidingProfile, etc., re-exported through `crates/worldwake-core/src/lib.rs:125-319`) — each is its own per-agent character axis per FND-22. Keeping slot weights inside `CognitiveProfile` is the anomaly. S148 D2 lifts slot weights to their own universal component, removes the embedded field per FND-28, and threads runtime reads through the established `GoalBeliefView` accessor pattern.

## Architecture Check

1. Aligns `PortfolioWeightsProfile` with the 30+ existing universal `*Profile` components — FND-22 (agent diversity through per-agent profile axes) is best served by separate components per axis. Reviewers locating per-agent variation find slot weights through the established profile-component convention rather than discovering them embedded in `CognitiveProfile`.
2. FND-28 clean migration: the embedded `slot_weights` field is removed atomically with the universal component's introduction. No shim, no parallel store, no transient dual-truth.
3. The `GoalBeliefView` accessor pattern keeps the AI crate's read locality intact (FND-14) — the planner reads weights through the belief-view abstraction, not through direct `World::get_component_*`. Future memory-fidelity work can add belief-staleness over the weights without rewriting the call sites.

## Landed Changes

### 1. Define `PortfolioWeightsProfile` universal component

Create `crates/worldwake-core/src/portfolio_weights_profile.rs`:

```rust
use crate::{Component, Permille, SlotKind};
use serde::{Deserialize, Serialize};

#[derive(Clone, Copy, Debug, Eq, PartialEq, Ord, PartialOrd, Serialize, Deserialize)]
pub struct PortfolioWeightsProfile {
    pub need_survival: Permille,
    pub pain_care: Permille,
    pub obligation_duty: Permille,
    pub economic_opportunity: Permille,
    pub social_motive: Permille,
    pub max_plans_normal: u8,
    pub max_plans_emergency: u8,
    pub max_plans_idle: u8,
}

impl Default for PortfolioWeightsProfile {
    fn default() -> Self {
        Self {
            need_survival: Permille::new_unchecked(1000),
            pain_care: Permille::new_unchecked(900),
            obligation_duty: Permille::new_unchecked(800),
            economic_opportunity: Permille::new_unchecked(600),
            social_motive: Permille::new_unchecked(400),
            max_plans_normal: 5,
            max_plans_emergency: 3,
            max_plans_idle: 5,
        }
    }
}

impl PortfolioWeightsProfile {
    pub fn weight_for(&self, slot: SlotKind) -> Permille {
        match slot {
            SlotKind::NeedSurvival        => self.need_survival,
            SlotKind::PainCare            => self.pain_care,
            SlotKind::ObligationDuty      => self.obligation_duty,
            SlotKind::EconomicOpportunity => self.economic_opportunity,
            SlotKind::SocialMotive        => self.social_motive,
        }
    }
}

impl Component for PortfolioWeightsProfile {}
```
