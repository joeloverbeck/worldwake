# S147HTNMETDEC-003: AgentSchemaContextProfile.disabled_methods and S111 lint extension

**Status**: COMPLETED
**Priority**: MEDIUM
**Effort**: Small
**Engine Changes**: Yes — extends the universal `AgentSchemaContextProfile` component with a new `disabled_methods` denylist field and updates the `ProfileHomogeneity` scenario lint.
**Deps**: `archive/tickets/S147HTNMETDEC-001.md` (MethodSchemaId)

## Problem

S147's per-agent method enablement is gated by the `disabled_methods` field on `AgentSchemaContextProfile`. The denylist convention (empty default = all enabled, scenarios opt agents out) was chosen during reassessment over the original allowlist proposal to (a) match the sibling `disabled_extractors` convention, (b) preserve Design Goal #5 (peasants don't know `FulfillBountyGroupHunt` by default at the registry level, but scenarios opt them out explicitly via the lint-checked denylist), and (c) satisfy FND-22 (diversity through concrete per-agent variation). Without this field, the `MethodSelector` (ticket 007) has no per-agent enablement surface and method gating must live in code rather than scenario data.

## Architecture Check

1. Denylist semantics (empty default = all enabled) match `disabled_extractors`. The original allowlist proposal (`enabled_methods` with default "all enabled") contradicted Design Goal #5 because a default of "all enabled" makes role-specific methods like `FulfillBountyGroupHunt` default-available to every agent, defeating diversity. The denylist puts the burden on scenario authors to opt agents out of methods, which is the right ergonomic direction for FND-22 (concrete per-agent variation).
2. `#[serde(default)]` on the new field preserves existing scenario RON deserialization without modification — no backwards-compatibility shim is needed and no SAVE_FORMAT_VERSION bump is required (sibling ticket 002 owns the only bump in S147).
3. Profile-doc regeneration (`scripts/profile_docs.py`) is in-scope to keep `docs/profiles/all-profiles.md` consistent with the code surface; deferring the doc regen would leave a doc/code mismatch invisible to Rust grep.
