## Problem

No golden E2E test isolates the baseline single-violation P15 chain in the live violation-id architecture: agent holds stale belief at the current place -> local perception detects a mismatch -> candidate generation records `ViolationKind::EntityMissing` and emits `GoalKind::InvestigateViolation { violation_id, place }` -> planner binds `investigate` -> commit records `SocialObservationKind::WitnessedAbsence` and resolves only that violation record. `golden_same_place_concurrent_violations_stay_distinct` proves the harder sibling-isolation case, but it does not provide a simpler single-incident golden that localizes regressions in the base path.

## Assumption Reassessment (2026-03-25)

1. Golden tests still live in `crates/worldwake-ai/tests/golden_*.rs`, and `crates/worldwake-ai/tests/golden_emergent.rs` is the right home for this scenario. It already contains the stronger sibling-isolation coverage for the same feature family in Scenario 13 (`golden_same_place_concurrent_violations_stay_distinct` / replay companion).
2. The live goal family is not `GoalKind::InvestigateMissing`. Current code uses `GoalKind::InvestigateViolation { violation_id, place }` in [crates/worldwake-core/src/goal.rs](/home/joeloverbeck/projects/worldwake/crates/worldwake-core/src/goal.rs), and candidate generation emits that goal from `emit_violation_goal()` in [crates/worldwake-ai/src/candidate_generation.rs](/home/joeloverbeck/projects/worldwake/crates/worldwake-ai/src/candidate_generation.rs).
3. The live architecture carries violation identity end to end. Candidate generation records `ViolationMemory` entries, planner payload binding matches on `violation_id`, and the `investigate` action resolves exactly the bound record in [crates/worldwake-systems/src/investigate_actions.rs](/home/joeloverbeck/projects/worldwake/crates/worldwake-systems/src/investigate_actions.rs). The ticket must assert on violation ids and resolution, not only on place-level goal identity.
4. The current baseline related golden is `golden_entity_missing_discovery_does_not_teleport_belief` in [crates/worldwake-ai/tests/golden_social.rs](/home/joeloverbeck/projects/worldwake/crates/worldwake-ai/tests/golden_social.rs). That scenario stops at passive discovery and stale-belief preservation. It does not prove planning, investigate execution, witnessed-absence aftermath, or violation-memory resolution.
5. This scenario does not require travel. The cleanest baseline is same-place local mismatch detection at the agent's current place. Travel is already covered elsewhere and would add timing noise without strengthening the violation contract under test.
6. `PerceptionProfile` and `ViolationDispositionProfile` remain required on the investigating agent. `PerceptionProfile` provides the local observation surface, and `ViolationDispositionProfile` is the gate that enables violation candidate emission.
7. The existing architecture is already cleaner than the original ticket narrative: carrying `violation_id` through the whole pipeline avoids aliasing same-place incidents together. The ticket should reinforce that architecture with a simple base-case golden rather than trying to reframe the system back to place-only `InvestigateMissing`.

## Architecture Check

1. A single-violation golden is still useful even though Scenario 13 exists. It isolates the core contract from same-place sibling bookkeeping, so regressions in baseline violation emission, planning, or commit aftermath fail in one place with a simpler causal story.
2. The live `InvestigateViolation { violation_id, place }` architecture is better than the original place-only proposal because it preserves incident identity across candidate generation, affordance enumeration, authoritative validation, and commit resolution. That is the robust, extensible design for future multiple-incident scenarios, and this ticket should validate it rather than dilute it.
3. No backwards-compatibility aliasing or shim goal variants should be introduced. If the test reveals a bug, fix the live violation-id path directly.

## Verification Layers

1. Local belief-perception mismatch records `ViolationKind::EntityMissing` and emits `GoalKind::InvestigateViolation { violation_id, place }` -> decision trace plus `ViolationMemory` inspection.
2. Planner binds the matching `investigate` step for that exact `violation_id` -> decision trace selected plan.
3. Authoritative start/commit uses the same `violation_id` -> action trace `ActionTraceDetail::Investigate { violation_id }`.
4. Investigation commit leaves concrete aftermath -> authoritative `AgentBeliefStore.social_observations` inspection for `SocialObservationKind::WitnessedAbsence`.
5. Only the selected violation record resolves -> authoritative `ViolationMemory` inspection.
6. Deterministic replay remains stable -> replay companion comparing world and event-log hashes.

## What to Change

### 1. New golden test in `crates/worldwake-ai/tests/golden_emergent.rs`

Scenario setup:
1. Create world with investigator A and subject E initially at Place P.
2. Give A `PerceptionProfile` and `ViolationDispositionProfile`; ensure action and decision tracing are enabled.
3. Seed A's belief store so A believes E is still at Place P from a prior direct observation.
4. Move E away from Place P via authoritative mutation that A does not observe.
5. Step one tick while A remains at Place P so fresh local perception contradicts the stale belief.

Tick execution:
6. Tick 0 (or the first stepped tick) should record `ViolationKind::EntityMissing { entity: E, expected_place: P }` and emit `GoalKind::InvestigateViolation { violation_id, place: P }`.
7. Planner should select the investigate goal and bind an `investigate` next step carrying that same `violation_id`.
8. Subsequent ticks should commit `investigate`.
9. On commit, `SocialObservationKind::WitnessedAbsence` should be recorded in A's belief store, and the matching `ViolationMemory` record should become resolved.

Assertions:
- Decision trace: `InvestigateViolation { violation_id, place: P }` was generated and selected
- Selected plan: next step is `investigate`
- Action trace: committed `investigate` carries the same `violation_id`
- Belief store: `SocialObservation { kind: WitnessedAbsence, subjects: (E, P) }` exists
- `ViolationMemory`: the matching violation record exists and is resolved after commit

### 2. Deterministic replay companion

Add a replay companion test that captures the scenario's inputs and replays them, verifying identical state hash at each tick.
