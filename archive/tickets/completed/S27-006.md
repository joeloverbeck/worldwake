# S27-006: Golden test — violation triggers ShareBelief to co-located listener

**Status**: COMPLETED
**Priority**: MEDIUM
**Effort**: Medium
**Engine Changes**: Yes — `worldwake-ai` supply-depletion detection must use the live resource-source belief surface
**Deps**: S27-001, S27-002, S27-003, S27-004, S27-005 (full violation pipeline + entity-missing golden as baseline)

## Problem

No golden E2E test proves the emergent reporting chain: agent detects commodity depletion -> belief updated -> social candidate pipeline emits `ShareBelief` to co-located listener -> Tell action propagates violation information. Without this, the P1 emergence claim (reporting arises from generic systems, not authored quest logic) has no integration proof.

## Assumption Reassessment (2026-03-25)

1. Live goal surface differs from the original ticket narrative. `crates/worldwake-core/src/goal.rs` defines `GoalKind::InvestigateViolation { violation_id, place }`, not `InvestigateMissing`, and `crates/worldwake-ai/tests/golden_emergent.rs` already contains violation goldens for entity-missing incidents. Ticket scope must target the current `InvestigateViolation` + `ShareBelief` architecture.
2. `emit_social_candidates()` runs before both `emit_recorded_violation_candidates()` and `emit_expectation_violation_candidates()` inside `generate_candidates_with_travel_horizon()` in `crates/worldwake-ai/src/candidate_generation.rs`. The clean architecture is that social sharing reacts to the speaker's already refreshed `known_entity_beliefs`, not to a violation-side mutation or a violation-specific report goal.
3. Existing coverage is split across layers: focused candidate-generation coverage already proves `SupplyDepleted` emits `InvestigateViolation` (`crates/worldwake-ai/src/candidate_generation.rs`, "Test 2: SupplyDepleted violation detected, InvestigateViolation candidate emitted"); golden coverage already proves entity-missing discovery (`crates/worldwake-ai/tests/golden_social.rs`) and investigation lifecycle (`crates/worldwake-ai/tests/golden_emergent.rs`). What is still missing is a golden that ties local supply depletion to the social Tell pipeline.
4. Reassessed against the live authoritative-belief projection, a source entity's prior expectation is carried by `BelievedEntityState.resource_source.available_quantity`, not by `last_known_inventory`. `build_observed_entity_snapshot()` in `crates/worldwake-core/src/belief.rs` clones the `ResourceSource` component but does not materialize its quantity into inventory. The ticket therefore needs a narrow engine fix: `SupplyDepleted` detection in `crates/worldwake-ai/src/candidate_generation.rs` must use the resource-source belief surface instead of depending on duplicated inventory state that real source beliefs do not populate.
5. `ShareBelief { listener, subject }` and Tell are already live and stable. `emit_social_candidates()` selects listeners from `social_listeners_at()` using co-located authoritative entities, then filters subjects through `listener_aware_relayable_subjects()`. The subject that matters for this ticket is the depleted source entity itself, not a violation-specific artifact.
6. Full action registries are still required because the intended proof boundary is mixed-layer golden E2E: perception refresh updates the speaker's belief about the source, decision tracing proves `ShareBelief` and `InvestigateViolation` coexist, action tracing proves Tell commit, and the listener's belief store proves physical information transfer.
7. For isolation, the listener should be co-located but unable to learn the depletion directly via perception. A blind or zero-fidelity `PerceptionProfile` on the listener is the clean setup because it proves the belief moved through Tell rather than through passive observation. The speaker still needs a `TellProfile`; the listener does not need direct observation of the source.
8. `ToldBeliefMemory` still matters, but deduplication is not the contract here. The contract is first propagation of a changed belief state. Existing social goldens already cover resend suppression and re-enable behavior in `crates/worldwake-ai/tests/golden_social.rs`.
9. Ordering correction: because perception refresh precedes candidate generation, and social candidates are emitted before violation candidates, the most defensible contract is "the first post-refresh planning tick exposes `ShareBelief` for the depleted subject and may also expose `InvestigateViolation` for the same local mismatch." The ticket should not claim that social candidate generation depends on violation-memory writes in the same pass.
10. This remains a golden E2E ticket, but it is not "test-only by assumption." The live code needs a narrow production fix so the `SupplyDepleted` candidate path lines up with the actual resource-source belief representation.
11. Mismatch + correction: the original ticket overstated coupling between violation detection and social emission, used the stale `InvestigateMissing` name, and pointed to `golden_social.rs` patterns as if the owning violation surface lived there. Reassessment also found that real source beliefs use `resource_source.available_quantity`, so the corrected scope is: add a narrow candidate-generation fix plus a new golden in `crates/worldwake-ai/tests/golden_emergent.rs` that proves current-belief propagation for a depleted source through generic `ShareBelief`/Tell while also confirming the local mismatch still surfaces as `InvestigateViolation`.

## Architecture Check

1. The cleaner architecture is the one already implied by the live code: perception updates the speaker's concrete belief about the source, the generic social pipeline decides whether that belief is worth relaying, and the violation subsystem separately offers `InvestigateViolation` for local follow-up. That is more robust and extensible than introducing a violation-specific reporting goal or making `ShareBelief` depend on violation-memory side effects.
2. The narrow engine fix is also architectural cleanup: `SupplyDepleted` should read the explicit `resource_source` belief snapshot instead of duplicating that state via `last_known_inventory`. That removes an accidental coupling between focused tests and a belief shape that real source observations do not produce.
3. No backwards-compatibility aliasing/shims introduced.

## What to Change

### 1. New golden test in `crates/worldwake-ai/tests/golden_emergent.rs`

Scenario setup:
1. Create world with Place P.
2. Create Agent A at Place P with a high-fidelity `PerceptionProfile`, `ViolationDispositionProfile`, and `TellProfile`.
3. Create Agent B at Place P with a blind or zero-fidelity `PerceptionProfile` so B cannot learn the depletion directly.
4. Create a resource source entity S at Place P with commodity C, initial quantity > 0.
5. Seed Agent A's belief store from authoritative observation so the prior expectation comes from `resource_source.available_quantity > 0`.
6. Deplete S's commodity C to quantity 0 via authoritative world mutation before the next step.

Tick execution:
7. Step one tick. Perception refresh updates A's belief about S to the depleted state.
8. That same planning tick should expose `ShareBelief { listener: B, subject: S }` from the generic social pipeline and `InvestigateViolation { violation_id, place: P }` from the local mismatch pipeline.
9. Allow sufficient ticks for A to execute Tell to B.
10. B's belief store updates from the Tell payload, not from direct perception.

Assertions:
- Decision trace (Agent A): `InvestigateViolation { .. }` candidate generated for Place P
- Decision trace (Agent A): `ShareBelief { listener: B, subject: S }` generated on the same first post-refresh planning tick
- Action trace: Tell action committed from A to B for subject S
- Belief store (Agent B): B's belief about source S reflects the depleted state and arrives only after Tell
- Replay companion: deterministic
