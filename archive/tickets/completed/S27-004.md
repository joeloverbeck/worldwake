# S27-004: Add investigate action definition and handler

**Status**: ✅ COMPLETED
**Priority**: HIGH
**Effort**: Medium
**Engine Changes**: Yes — add the missing `investigate` authoritative action surface in `worldwake-systems`, plus the minimum `worldwake-sim` duration support needed to keep investigation duration profile-driven
**Deps**: S27-001, S27-002, S27-003; spec `specs/S27-expectation-violation-goals.md`

## Problem

`GoalKind::InvestigateMissing { place }` already exists in `worldwake-core`, is emitted by `emit_expectation_violation_candidates()` in `worldwake-ai`, and is modeled through `PlannerOpKind::Investigate`. But `worldwake-systems` still has no registered `ActionDomain::Generic` / `"investigate"` action, so the authoritative action catalog does not contain the terminal operator the planner is already targeting. The result is an architectural gap between the AI/planner surface and the live action surface.

This ticket closes that gap by adding the authoritative `investigate` action and verifying the full action-lifecycle contract it needs to satisfy. The action must produce concrete aftermath rather than abstract planner-only completion: an event-log discovery record and a `SocialObservationKind::WitnessedAbsence` artifact in the actor's `AgentBeliefStore`.

The remaining gap is authoritative action coverage plus a stronger end-to-end proof once the action exists.
9. Ordering in this ticket is action-lifecycle ordering, not “later tick means later cause.” If verification depends on same-tick start/commit/abort behavior, action traces or direct authoritative state inspection are the correct proof surfaces.

## Architecture Check

1. The clean architecture is to make investigation a first-class action definition that the planner can legally target through the same catalog every other live action uses. That preserves agent symmetry, keeps AI/planner assumptions aligned with authoritative execution, and avoids any planner-only “pretend terminal op” path.
2. The clean duration design is to extend `DurationExpr` with investigation-specific runtime resolution rather than baking a fixed number into the action or trying to mutate duration from `on_start`. The runtime already centralizes dynamic durations there for trade, combat, treatment, consultation, travel, and metabolism. Investigation should use the same mechanism instead of introducing a second duration authority.
3. No backwards-compatibility aliases, shadow operators, or duplicate authoritative paths should be introduced. Broken callers should be updated to the live action surface; no shim layer should preserve a planner-only investigate concept beside the real action.

## What to Change

### 1. Add a real authoritative `investigate` action in `worldwake-systems`

Create `crates/worldwake-systems/src/investigate_actions.rs` following the existing action-definition/handler pattern:

- `ActionDomain::Generic`
- target is the investigation place
- actor constraints/preconditions must enforce:
  - actor alive
  - actor not incapacitated
  - actor at the investigation place
- `Interruptibility::FreelyInterruptible`
- `VisibilitySpec::SamePlace`
- causal event tags include `EventTag::Discovery`
- `on_commit()` records a `SocialObservation { kind: WitnessedAbsence, subjects: (missing_subject, investigated_place), place: investigated_place, observed_tick: current_tick, source: PerceptionSource::DirectObservation }` in the actor's `AgentBeliefStore`
- `on_abort()` leaves no investigation artifact behind

The handler should stay minimal and authoritative. It should not attempt to “simulate” planner behavior or add speculative evidence systems that belong to later crime/investigation specs.

### 2. Add investigation duration support where durations already belong

Extend `crates/worldwake-sim/src/action_semantics.rs` / `DurationExpr` with an investigation-specific dynamic duration that resolves from `ViolationDispositionProfile.investigation_duration_ticks`, falling back to `NonZeroU32::new(3).unwrap()` when the profile is absent. Update the belief-side duration estimation path consistently if needed so planning/affordance estimation uses the same contract.

This ticket should not hardcode a fixed duration in the action def if the spec and current architecture already require per-agent investigation diversity.

### 3. Register the action in the shared authoritative catalog

- add `pub mod investigate_actions;` and public re-export wiring in `crates/worldwake-systems/src/lib.rs`
- register the definition/handler from `crates/worldwake-systems/src/action_registry.rs`
- extend the existing registry completeness test to require `"investigate"`

### 4. Keep affordance/payload scope minimal

Do not pre-emptively change `crates/worldwake-sim/src/action_payload.rs` or `crates/worldwake-sim/src/affordance_query.rs` unless implementation proves the existing target/precondition machinery cannot express the investigate affordance. The current reassessment indicates those changes are likely unnecessary.

### 5. Strengthen tests at the right layer

Add focused `worldwake-systems` tests for:

- definition/registration
- authoritative start success/failure
- duration contract
- commit aftermath
- abort no-op aftermath

Add `worldwake-sim` coverage only if the new `DurationExpr` branch needs direct resolution/start-gate tests. If an end-to-end `worldwake-ai` test is strengthened, it should prove the action actually executes rather than merely that belief correction remains local.
