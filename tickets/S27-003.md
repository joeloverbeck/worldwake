# S27-003: Implement emit_expectation_violation_candidates()

**Status**: PENDING
**Priority**: HIGH
**Effort**: Medium
**Engine Changes**: Yes — new candidate generation family in AI pipeline, GoalBeliefView extensions
**Deps**: S27-001 (ViolationKind, ViolationMemory, ViolationDispositionProfile types), S27-002 (GoalKind::InvestigateMissing, GoalKindTag)

## Problem

No candidate generation function compares prior beliefs against current perception to detect violations. Without this, agents cannot notice when expected entities go missing, supplies deplete, or entities die — and consequently cannot emit investigation goals. This is the core P15 implementation: surprise comes from violated expectation.

## What to Change

### 1. New function `emit_expectation_violation_candidates()` in `crates/worldwake-ai/src/candidate_generation.rs`

Algorithm as specified in the spec's "Candidate Generation" section:
- Early return if agent has no current place (in transit) or no `ViolationDispositionProfile`.
- Read agent's `ViolationMemory` and known entity beliefs.
- Build observed entity set at current place via `entities_at()`.
- For each belief entry: detect `EntityMissing`, `SupplyDepleted`, `EntityDead` violations.
- `EntityDead` records in ViolationMemory only — no goal emitted.
- For `EntityMissing` and `SupplyDepleted`: check ViolationMemory suppression, check BlockedIntentMemory suppression, then emit via `emit_candidate_with_trace()` with `GoalKind::InvestigateMissing { place }`, appropriate `Evidence` and `EvidenceTrace` with `KnowledgePath`.
- Record new violations in ViolationMemory with TTL from profile.

### 2. Integrate into `generate_candidates_with_travel_horizon()` in `crates/worldwake-ai/src/candidate_generation.rs`

Add `emit_expectation_violation_candidates(&mut candidates, &mut diagnostics, &ctx);` as the 7th emitter call, after the existing 6.

### 3. Possible `GoalBeliefView` extension in `crates/worldwake-sim/src/belief_view.rs`

If `commodity_quantity()` or equivalent read for supply depletion detection is not already on the trait, add it. Also check if `believed_owner_of()` is available for ownership-bonus motive (used in ranking, but the evidence entities need to be set here for ranking to use later).

### 4. ViolationMemory mutation during candidate generation

The emitter mutates `ViolationMemory` (recording new violations). This requires either:
- A mutable reference to the component (if candidate generation has write access), OR
- A deferred mutation list that is applied after candidate generation completes.

Check which pattern the existing emitters use for state mutation during candidate generation (e.g., does any existing emitter write to agent components?). Follow the same pattern.

## Acceptance Criteria

### Tests That Must Pass

1. Agent at Place P with stale belief "Entity E at P" but E absent from `entities_at(P)` -> `EntityMissing` violation detected, `InvestigateMissing { place: P }` candidate emitted
2. Agent at Place P with stale belief "commodity C available at source S at P, qty > 0" but observed qty == 0 -> `SupplyDepleted` violation detected, `InvestigateMissing { place: P }` candidate emitted
3. Agent at Place P observes entity E dead (previously believed alive) -> `EntityDead` recorded in ViolationMemory, NO `InvestigateMissing` candidate emitted
4. Already-recorded unexpired violation in ViolationMemory -> no duplicate candidate emitted
5. `BlockedIntentMemory::is_blocked_for_search()` returns true for investigation GoalKey -> no candidate emitted
6. Agent has no `ViolationDispositionProfile` -> function returns early, no candidates
7. Agent in transit (no current place) -> function returns early, no candidates
8. Agent's self-entity skipped (no self-violation)
9. Entity with no prior belief at agent's current place -> no violation detected
10. Emitted candidates include `EvidenceTrace` with `KnowledgePath` showing belief-observation contradiction
11. Existing suite: `cargo test -p worldwake-ai`
12. Existing suite: `cargo clippy -p worldwake-ai`

### Invariants

1. Violation detection is local-only (P7): only beliefs about entities at agent's current place are checked
2. Detection runs inside candidate generation, not as a separate system pass (architectural consistency)
3. `EntityDead` never emits `InvestigateMissing` (spec decision: corpse IS the evidence)
4. All emitted candidates use `emit_candidate_with_trace()` (S28 compliance)
5. No direct world state reads — all detection uses `GoalBeliefView` methods (P12)
