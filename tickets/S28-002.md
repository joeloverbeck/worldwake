# S28-002: Thread tracing flag and instrument need/self-consume candidates

**Status**: PENDING
**Priority**: HIGH
**Effort**: Medium
**Engine Changes**: Yes — `GenerationContext` gains `tracing_enabled`, need emitters populate `KnowledgePath`
**Deps**: S28-001

## Problem

Need-driven candidates (eat, drink, sleep, relieve, wash) are the most common goal family. Their knowledge paths must record which homeostatic need level motivated the candidate (self-knowledge) and which entity beliefs provided evidence for commodity sources (sellers, resource sources, loose lots).

## Assumption Reassessment (2026-03-25)

1. `GenerationContext` at `candidate_generation.rs:109-118` has 8 fields. No `tracing_enabled` field exists.
2. `generate_candidates_with_travel_horizon()` at line 145 constructs `GenerationContext` at line 165. It does not currently receive a tracing flag.
3. `emit_self_consume_candidates` (line 682) calls `emit_candidate_with_trace` at line 765 — already produces `EvidenceTrace`. Can attach `KnowledgePath` alongside.
4. `emit_need_driven_candidates` (line 707) dispatches to `emit_sleep_goal` (line 781), `emit_relieve_goal` (line 798), `emit_wash_goal` (line 815). These 3 sub-emitters call `emit_candidate()` (no trace) — they do NOT produce `CandidateEvidenceTrace` entries.
5. `known_entity_beliefs()` at line 247, 903, etc. returns `Vec<(EntityId, BelievedEntityState)>` which carries `.source: PerceptionSource` and `.observed_tick: Tick` — the data needed for `BeliefProvenance`.
6. `emit_candidate_with_trace` at line 1216 takes `evidence_trace: EvidenceTrace` and stores it in `diagnostics.evidence` keyed by `GoalKey`. The `KnowledgePath` should be attached to the `CandidateEvidenceTrace` at this point.
7. This is an AI diagnostic ticket. The instrumentation layer is candidate generation. No full action registries required — the existing `TestBeliefView` harness in `candidate_generation.rs` is sufficient.
8. Single-layer: candidate generation instrumentation only. No ranking, search, or execution changes.

## Architecture Check

1. Threading `tracing_enabled: bool` through `GenerationContext` is the cleanest way to gate provenance lookups — it avoids passing an `Option<&DecisionTraceSink>` through the entire generation pipeline. The flag is set from `AgentTickDriver::trace_sink.is_some()` at the call site in `agent_tick/candidates.rs`.
2. No backward-compatibility shims. The flag defaults to `false` when not explicitly set.

## Verification Layers

3. `tracing_enabled=true` + seller/resource-source evidence → `KnowledgePath.entity_beliefs` contains `BeliefProvenance` with correct `PerceptionSource` and `observed_tick` → focused unit test

## What to Change

### 1. Add `tracing_enabled` to `GenerationContext`

In `candidate_generation.rs`, add `tracing_enabled: bool` field to `GenerationContext`. Set it to `false` in `generate_candidates_with_travel_horizon()`.

### 2. Thread tracing flag from `AgentTickDriver`

In `crates/worldwake-ai/src/agent_tick/candidates.rs` (or wherever the driver calls `generate_candidates_with_travel_horizon`), pass `trace_sink.is_some()` as the tracing flag. This requires adding a `tracing_enabled` parameter to `generate_candidates_with_travel_horizon()`.

### 3. Instrument `emit_self_consume_candidates`

When `ctx.tracing_enabled` is true:
- Add `SelfKnowledgeProvenance::NeedLevel { need: HomeostaticNeedId::Hunger, permille }` to the `KnowledgePath.self_knowledge`
- For each commodity holder (seller, resource source, loose lot) in the evidence trace, look up the matching entry in `known_entity_beliefs()` and construct `BeliefProvenance { subject, aspect: HasCommodity/IsResourceSource, source, observed_tick }`
- Attach the `KnowledgePath` to the `CandidateEvidenceTrace` before storing in diagnostics

### 4. Upgrade `emit_sleep_goal`, `emit_relieve_goal`, `emit_wash_goal` to use `emit_candidate_with_trace`

These currently use `emit_candidate()`. Upgrade them to:
- Accept `diagnostics: &mut CandidateGenerationDiagnostics` parameter
- Construct an `EvidenceTrace` (may be empty — these are self-only needs with no external entity evidence)
- When `tracing_enabled`: populate `KnowledgePath.self_knowledge` with the appropriate `NeedLevel` entry
- Call `emit_candidate_with_trace()` instead of `emit_candidate()`

### 5. Update call sites

Update `emit_need_driven_candidates` to pass `diagnostics` to the sub-emitters it dispatches to.
