# S174SHESLESUR-002: Scenario contract — PlaceDef.rest_capacity + MetabolismProfile.rough_sleep_recovery_floor

**Status**: PENDING
**Priority**: HIGH
**Effort**: Small
**Engine Changes**: Yes — new field on universal `MetabolismProfile` agent profile; new optional field on scenario-loader `PlaceDef`; profile doc regeneration
**Deps**: `archive/tickets/S174SHESLESUR-001.md` (`MetabolismProfile` field rides ticket 001's SAVE_FORMAT_VERSION bump via `#[serde(default)]`; scenario contract for `RestCapacity` requires the component registration from 001)

## Problem

For S174's two-path Sleep schema to be exercisable from scenario authoring, `PlaceDef` needs a `rest_capacity` field that wires through `spawn_place` to write the `RestCapacity` component (introduced in ticket 001). For rough-sleep recovery to be capped per S174 D9, `MetabolismProfile` needs a `rough_sleep_recovery_floor: Permille` field with a meaningful default and `#[serde(default)]` so the 20 existing RON scenarios continue to deserialize unchanged.

## Architecture Check

1. The two field additions are bundled into one ticket because both are scenario-contract additions sharing the same `#[serde(default)]` discipline and the same Files-to-Touch shape (struct field + serde default + downstream consumer + doc regen). Splitting them into separate tickets would duplicate test scaffolding without architectural benefit.
2. Choosing the optional pattern for `rest_capacity` (`Option<u32>`, omitted by default) matches the existing `PlaceDef` precedent (`sleep_quality`, `place_dirtiness`, `latrine_fullness` all use `Option` + `#[serde(default)]`). Places that don't author `rest_capacity` simply have no `RestCapacity` component — the absence is the well-defined "not a known rest site" state, matching `RestCapacity`'s semantic from ticket 001.
3. Choosing the universal pattern for `rough_sleep_recovery_floor` (default `Permille::new(300)`, absorbed by `MetabolismProfile::default()`) matches `MetabolismProfile`'s universal-profile precedent. Every agent has this field whether or not the scenario authored it. No `Option` indirection is needed because `Permille::new(300)` is a meaningful baseline (rough sleep is always partially restorative).

In `crates/worldwake-core/src/needs.rs:141-178`, add to the `MetabolismProfile` struct:

```rust
/// Hard ceiling on per-tick fatigue recovery when sleeping rough (no known
/// rest site). The sleep action handler applies this floor regardless of the
/// place's `SleepQualityProfile.recovery_modifier`. Default permille value

/// restorative but cannot match shelter-quality recovery.

pub rough_sleep_recovery_floor: Permille,
```

Add a free helper function:

```rust
fn default_rough_sleep_recovery_floor() -> Permille {
    Permille::new(300)
}
```

Update `MetabolismProfile::default()` (impl Default block) to set the new field to `default_rough_sleep_recovery_floor()`.
