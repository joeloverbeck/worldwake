## Problem

No golden E2E test proves the full P15 chain: agent holds stale belief -> arrives at location -> perceives mismatch -> emits investigation goal -> executes investigate action -> produces SocialObservation(WitnessedAbsence). Without this coverage, the violation-to-investigation pipeline has no integration proof.

The new test fits `golden_emergent.rs` (violation detection is a cross-system emergence pattern). Confirmed by glob.
2. Golden test harness (`GoldenTestHarness` or equivalent) provides: world setup, agent creation with profiles, belief seeding, tick stepping, active action querying, belief store inspection, decision trace access, action trace access. Confirmed by reading existing golden test patterns.
3. `PerceptionProfile` is required on agents that need to observe entities (CLAUDE.md: "Golden production tests require `PerceptionProfile` on agents that need to observe post-production output"). The investigating agent needs `PerceptionProfile` to perceive entities at the investigation place.
4. This is a golden E2E ticket. The intended verification layer is the full agent decision pipeline from candidate generation through action execution. Full action registries are required.
5. The scenario depends on belief-perception mismatch ordering: stale belief persists from prior observation, fresh perception at the location does NOT show the entity, candidate generation detects the mismatch. This timing is inherent in the perception-then-candidate-generation tick order (CLAUDE.md: tick system execution order).
6. `golden_entity_missing_discovery_does_not_teleport_belief` already exists in `golden_social.rs:1325` — this is a related but different test. It tests that discovery does NOT teleport belief. S27-005 tests that violation detection TRIGGERS investigation. No overlap.

## Verification Layers

1. Violation detection (`EntityMissing`) emits `InvestigateMissing` candidate -> decision trace shows candidate in generation diagnostics
2. Planner finds plan for `InvestigateMissing` goal -> decision trace shows plan search success
3. Agent's active action becomes `investigate` -> `agent_active_action_name()` or action trace
4. Investigation completes and produces `SocialObservation(WitnessedAbsence)` -> agent belief store inspection
5. `ViolationMemory` records the violation -> component state inspection
6. Deterministic replay produces identical outcome -> replay companion test
7. Multi-layer golden ticket: candidate generation (decision trace) + action execution (action trace or state delta) + belief update (belief store).

## What to Change

### 1. New golden test in `crates/worldwake-ai/tests/golden_emergent.rs`

Scenario setup:
1. Create world with Place P and Place Q.
2. Create Agent A at Place Q with `PerceptionProfile`, `ViolationDispositionProfile`, `ViolationMemory` (empty).
3. Create Entity E (e.g., an item lot or another agent) at Place P.
4. Seed Agent A's belief store: A believes E is at Place P (via a prior observation record in `AgentBeliefStore.known_entities` with `last_known_place: Some(P)`, `observed_tick: Tick(1)`).
5. Move Entity E from Place P to Place Q (or remove E from P) via authoritative world mutation — A does NOT observe this.
6. Move Agent A to Place P (via travel or direct placement).

Tick execution:
7. Step ticks. A arrives at P. Perception refresh shows E is NOT at P. A's stale belief says E should be at P.
8. Candidate generation detects `EntityMissing { entity: E, expected_place: P }`.
9. A selects `InvestigateMissing { place: P }` as active goal.
10. A executes `investigate` action (profile-driven duration, e.g., 3 ticks).
11. On investigation commit: `SocialObservation(WitnessedAbsence)` recorded in A's belief store.

Assertions:
- Decision trace: `InvestigateMissing` candidate was generated with correct evidence and knowledge path
- Action trace or active action: agent executed `investigate` action at Place P
- Belief store: `SocialObservation { kind: WitnessedAbsence, subjects: (E, P) }` exists
- `ViolationMemory`: violation recorded with correct kind and TTL

### 2. Deterministic replay companion

Add a replay companion test that captures the scenario's inputs and replays them, verifying identical state hash at each tick.
