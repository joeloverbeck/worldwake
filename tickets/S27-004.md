# S27-004: Add investigate action definition and handler

**Status**: PENDING
**Priority**: HIGH
**Effort**: Medium
**Engine Changes**: Yes — new action definition, handler, affordance registration in worldwake-systems
**Deps**: S27-001 (ViolationDispositionProfile for duration, ViolationMemory for TTL update, SocialObservationKind::WitnessedAbsence)

## Problem

No action exists for agents to execute an investigation. The planner can select `InvestigateMissing` goals (S27-002) and candidates are generated (S27-003), but without an `investigate` action definition and handler, the action framework cannot start, progress, or commit the investigation. The handler must produce concrete aftermath (P9): a `SocialObservation(WitnessedAbsence)` record in the agent's belief store.

## Assumption Reassessment (2026-03-25)

1. Action definitions follow the pattern in `crates/worldwake-systems/src/needs_actions.rs`, `production_actions.rs`, `trade_actions.rs`, etc. Each defines an `ActionDef` with domain, preconditions, duration, interruptibility, visibility, and event tags. Confirmed by file read.
2. Action handlers implement the handler trait from `crates/worldwake-sim/src/action_handler.rs`. Handlers have `on_start()`, `on_tick()`, `on_commit()`, `on_abort()` methods. Confirmed by file read.
3. Action registration happens in `crates/worldwake-systems/src/action_registry.rs` via `register_all_actions()` / `build_full_action_registries()`. Confirmed.
4. Affordance generation in `crates/worldwake-sim/src/affordance_query.rs` uses `get_affordances()` which evaluates constraints/preconditions per action def. The investigate action needs to be discoverable here. Confirmed pattern.
5. `AgentBeliefStore` in `crates/worldwake-core/src/belief.rs` has a method for recording `SocialObservation` entries. Need to verify exact method name. The `SocialObservation` struct takes `kind`, `subjects`, `place`, `observed_tick`, `source`.
6. `ViolationDispositionProfile.investigation_duration_ticks` (S27-001) provides the duration. If profile is absent, fallback to `NonZeroU32::new(3).unwrap()`.
7. `EventTag::Discovery` — need to verify this variant exists. If not, it needs to be added. Check `crates/worldwake-core/src/event_tag.rs`.
8. The investigate action needs access to `ViolationMemory` (to extend TTL on commit) and to `AgentBeliefStore` (to record `SocialObservation`). The commit handler receives a `WorldTxn` which provides component access.

## Architecture Check

1. Follows the same action definition + handler pattern as `tell_actions.rs`, `needs_actions.rs`, etc. Domain is `ActionDomain::Generic` (not system-specific). No novel patterns.
2. No backwards-compatibility aliasing/shims introduced.

## What to Change

### 1. New file `crates/worldwake-systems/src/investigate_actions.rs`

Define:
- `investigate` action definition:
  - Domain: `ActionDomain::Generic`
  - Duration: read from `ViolationDispositionProfile.investigation_duration_ticks` at start time; fallback `NonZeroU32::new(3).unwrap()` if profile absent
  - Preconditions: agent at investigation place, agent not incapacitated
  - Interruptibility: `FreelyInterruptible`
  - Visibility: `SamePlace`
  - Event tags: `BTreeSet::from([EventTag::Discovery])`
- Handler:
  - `on_start()`: standard start (no-op beyond precondition validation)
  - `on_tick()`: standard tick progression (continue)
  - `on_commit()`:
    1. Record investigation event in event log with `EventTag::Discovery`
    2. Update `ViolationMemory`: extend TTL for the investigated violation using `ViolationDispositionProfile.violation_memory_retention_ticks`
    3. Record `SocialObservation { kind: WitnessedAbsence, subjects: (missing_entity, place), place: current_place, observed_tick: current_tick, source: PerceptionSource::DirectObservation }` in agent's `AgentBeliefStore`
  - `on_abort()`: no-op (interrupted investigation produces no artifact)

### 2. Register action definition and handler

In `crates/worldwake-systems/src/action_registry.rs`: register the investigate action def in `ActionDefRegistry` and handler in `ActionHandlerRegistry` via `register_all_actions()`.

### 3. Add module to `crates/worldwake-systems/src/lib.rs`

Add `pub mod investigate_actions;`.

### 4. Add `EventTag::Discovery` if missing

Check `crates/worldwake-core/src/event_tag.rs`. If `Discovery` variant does not exist, add it. This is a small change to core that logically belongs with the action.

### 5. Affordance generation

Ensure the investigate action is discoverable by `get_affordances()` in `crates/worldwake-sim/src/affordance_query.rs`. The action's preconditions (co-location, not incapacitated) should be evaluable by the existing constraint/precondition framework. If the investigate action needs a specific affordance generation function (like other action families), add it.

### 6. ActionPayload extension (if needed)

If the investigate action needs to carry data (e.g., which entity is being investigated, which place), check whether `ActionPayload` enum in `crates/worldwake-sim/src/action_payload.rs` needs a new variant. The investigation place might come from the action's target or from the `GoalKind` context.
