**Status**: PENDING
**Priority**: HIGH
**Effort**: Large

**Deps**: 008 (planner integration), 009 (trace + diagnostics), 010 (observer rendering)

## Problem

S147 D10 ships 6 golden scenarios that prove the HTN method system works end-to-end in the simulation. Without these goldens, the per-component unit tests in tickets 001-010 prove the parts compile and behave individually, but not that they integrate correctly under the agent tick, action lifecycle, and event log. The goldens are the regression guard for S147's stated behavior contract and the proof surface that the FOUNDATIONS alignment claims (FND-7, FND-14, FND-20, FND-22, FND-26, FND-28, FND-29, FND-29A, FND-30) hold under live planning.

## Verification Layers

1. End-to-end method selection produces expected actions → action trace (each golden asserts the sequence of committed actions matches the expected method's subgoal expansion).
2. Method choice is recorded in decision trace → decision trace (each golden asserts `PlanAttemptTrace.method_trace.method_id` equals the expected method).
3. Typed failure attribution flows to authoritative chain → event-log delta (the failure golden asserts a `Discrepancy::MethodFailure(MethodFailureContext { kind: SubgoalUnachievable, … })` is emitted on the typed channel).
4. Flat-GOAP fallback produces unchanged behavior when methods are disabled → action trace + existing golden suite (regression guard).
5. Determinism golden runs the same scenario+seed twice and asserts identical method choices via `MethodPlanAttemptTrace.method_id` and `motive_score` equality across runs.

## What to Change

### 1. New golden test file

New file `crates/worldwake-ai/tests/golden_htn_methods.rs` with 6 scenarios per spec D10:

1. **`golden_fulfill_bounty_direct_end_to_end`** — agent has direct target knowledge (belief view satisfies `TargetLastSeenKnown` precondition) → `FulfillBountyDirect` method selected → subgoals execute → bounty fulfilled (ClaimBounty action committed). Asserts `method_trace.method_id == FulfillBountyDirect`.

2. **`golden_fulfill_bounty_investigation_then_direct_chain`** — agent lacks target location initially → `FulfillBountyInvestigation` selected (witness ask) → after witness updates belief, next-tick selection re-routes to `FulfillBountyDirect`. Asserts method-choice transition recorded in trace over consecutive ticks.

3. **`golden_produce_with_gather_for_three_input_recipe`** — `ProduceCommodity{recipe="Bake Bread"}` with agent missing 3 inputs but knowing sources → `ProduceWithGather` selected → 3 AcquireCommodity subgoals execute in order → final Craft action commits. Asserts subgoal sequence matches method definition.

4. **`golden_method_disabled_fallback_to_flat_goap`** — agent with `disabled_methods = {ProduceFromOwnedStock, ProduceWithGather, ProduceWithPurchase}` on `ProduceCommodity` goal → `select_method` returns `None` → flat-GOAP path executes (unchanged from pre-S147 behavior). Asserts `method_trace.method_id == None` and the produced stages match the existing flat-GOAP output for the same scenario.

5. **`golden_method_failure_records_typed_discrepancy`** — method selected, subgoal becomes unachievable mid-execution (e.g., target moves between observation and attack) → `MethodFailureMode::SubgoalUnachievable` recorded in trace AND `Discrepancy::MethodFailure(MethodFailureContext { kind: SubgoalUnachievable, … })` emitted on typed channel. Asserts both surfaces carry consistent context.

6. **`golden_method_selection_is_deterministic`** — identical scenario, identical seed, two runs → asserts `MethodPlanAttemptTrace.method_id` and `motive_score` are byte-identical across runs.

### 2. Regenerate golden inventory

Run `python3 scripts/golden_inventory.py --write --check-docs` after the new file is in place. The script updates `docs/generated/golden-e2e-inventory.md` and `docs/generated/golden-scenario-index.md` automatically.

### 3. Scenario fixtures

Reuse existing scenario RON fixtures where possible (e.g., the bounty/justice scenarios for bounty methods, the production scenarios for produce methods). Where a method-specific scenario is required (e.g., the method-disabled fallback case), add a new RON fixture under `scenarios/` and reference it from the golden.

### Invariants

1. Determinism — every golden's method choices and trace contents are byte-identical across repeated runs with the same seed (golden #6 explicitly tests this; the other 5 inherit the property by virtue of using fixed seeds).

3. Flat-GOAP fallback equivalence — when methods are disabled, the produced stages match the pre-S147 flat-GOAP output for the same scenario (golden #4 asserts this).
4. No new `PlannerOpKind` variants — every method's subgoals reference real existing variants.
