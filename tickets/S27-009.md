# S27-009: Golden test — concurrent same-place violations stay distinct

**Status**: PENDING
**Priority**: MEDIUM
**Effort**: Medium
**Engine Changes**: None — golden coverage for `S27-008`
**Deps**: S27-004, S27-005, S27-008; spec `specs/S27-expectation-violation-goals.md`

## Problem

After `S27-008`, the architecture should treat each recorded violation as a distinct incident even when multiple incidents share one place. That needs an end-to-end proof, not just focused unit tests. Without a golden scenario, the system could still regress back to place-scoped investigate behavior while keeping most unit coverage green.

The missing proof surface is a same-place concurrency scenario: one agent carries two stale expectations about the same place, both expectations are violated, and the AI must keep those two investigations distinct through candidate generation, selection, action execution, and aftermath.

## Assumption Reassessment (2026-03-25)

1. Golden tests live under `crates/worldwake-ai/tests/golden_*.rs`. The right home is `crates/worldwake-ai/tests/golden_emergent.rs` because this is a cross-layer emergence scenario, not a narrow social-only or production-only test.
2. The current live golden test `golden_entity_missing_discovery_does_not_teleport_belief` in `crates/worldwake-ai/tests/golden_social.rs` proves locality of belief correction, not distinct incident identity. It does not cover concurrent same-place anomalies.
3. The current live engine still uses the place-scoped `GoalKind::InvestigateMissing { place }` contract, so this golden ticket is blocked on `S27-008`. Once `S27-008` lands, the live goal/action contract should expose stable violation identity and this ticket should test that new surface directly.
4. Golden harness support already exists for the proof surfaces this scenario needs: belief seeding, world mutation, tick stepping, decision traces, action traces, and belief-store inspection. Existing golden patterns across `golden_emergent.rs` and `golden_social.rs` already use those tools.
5. This scenario depends on action-lifecycle ordering and decision identity, not just later belief-state convergence. The test should therefore assert through decision traces and action traces first, then use belief/social-observation state as aftermath proof.
6. The scenario must intentionally exclude lawful competing branches that would blur the identity proof. The clean isolation is one investigator agent, one shared place, two violated expectations, no colocated listeners, no nearby hostile pressure, and no other higher-priority survival crisis.
7. FOUNDATIONS Principle 15 requires violated expectation to arise from prior belief, not omniscient absence detection. The test must seed stale beliefs first, then let local observation contradict them at the place.
8. Mismatch + correction: this is not a “does investigation happen at all?” test. `S27-005` already covers the basic investigation chain. This ticket is specifically about keeping same-place incidents distinct after the identity-bearing redesign.

## Architecture Check

1. A dedicated golden scenario is the cleanest regression guard because the bug class is cross-layer: identity can be lost in candidate generation, goal keying, plan validation, or authoritative investigate start. One scenario can observe the whole chain without inventing new harness infrastructure.
2. The scenario should assert exact incident identity, not merely “two investigations eventually happened at the same place.” Place-only assertions would recreate the same ambiguity the ticket is meant to prevent.
3. No compatibility aliasing or fallback behavior should be accepted in the golden proof. If the engine still allows “investigate whichever violation is latest at the place,” the scenario should fail.

## Verification Layers

1. Two distinct violation-driven investigation candidates exist at the same place -> decision trace
2. The selected investigate action carries one exact violation identity -> action trace and/or selected-plan inspection
3. The first investigate commit records aftermath for the selected violation only -> authoritative belief/social-observation state
4. The sibling violation remains outstanding and later produces its own investigate selection -> later decision trace and action trace
5. Deterministic replay preserves the same incident ordering and aftermath -> replay companion golden test

## What to Change

### 1. Add a same-place concurrent-violation golden scenario

Create a scenario in `crates/worldwake-ai/tests/golden_emergent.rs` with one investigating agent and one place `P`.

Setup:

1. Seed the investigator with two stale beliefs about `P`.
2. Use two distinct concrete violations at the same place, for example:
   - one `EntityMissing` expectation for entity `E`
   - one `SupplyDepleted` expectation for source `S`
3. Mutate authoritative state so both expectations are violated before the agent re-observes the place.
4. Ensure the agent has the profiles needed to perceive, generate violation goals, and execute investigation.
5. Exclude unrelated lawful branches that would outrank or interrupt investigation.

Assertions:

1. The first relevant decision trace shows two distinct investigation candidates with the same place but different violation identities.
2. The first selected `investigate` action is bound to one exact violation identity.
3. The first commit records aftermath only for that selected violation.
4. The sibling violation remains available and is later investigated separately rather than disappearing because the place was already “investigated.”
5. The final belief/social-observation state shows two distinct aftermath artifacts, one per original violation.

### 2. Add deterministic replay companion coverage

Add a replay companion test for the same scenario so the violation-selection order and aftermath remain deterministic under replay.
