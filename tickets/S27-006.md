# S27-006: Golden test — violation triggers ShareBelief to co-located listener

**Status**: PENDING
**Priority**: MEDIUM
**Effort**: Medium
**Engine Changes**: None
**Deps**: S27-001, S27-002, S27-003, S27-004, S27-005 (full violation pipeline + entity-missing golden as baseline)

## Problem

No golden E2E test proves the emergent reporting chain: agent detects commodity depletion -> belief updated -> social candidate pipeline emits `ShareBelief` to co-located listener -> Tell action propagates violation information. Without this, the P1 emergence claim (reporting arises from generic systems, not authored quest logic) has no integration proof.

## Assumption Reassessment (2026-03-25)

1. `emit_social_candidates()` in `crates/worldwake-ai/src/candidate_generation.rs` evaluates relayable subjects via `listener_aware_relayable_subjects()`. After violation updates the agent's beliefs (entity missing / supply depleted), the social pipeline considers these updated beliefs as potentially shareable. Confirmed by S28/E15b/E15c completed work.
2. `ShareBelief { listener, subject }` goal already exists as `GoalKind` variant 15. The Tell action is fully implemented (E15b). Confirmed.
3. `TellProfile` is required on agents that act as information sharers. `PerceptionProfile` is required on agents that need to observe. The listener agent needs a `TellProfile` on the sharing agent, and appropriate belief state. Confirmed by golden_social.rs patterns.
4. `ToldBeliefMemory` prevents re-telling the same fact to the same listener (E15c). This ensures the test can assert a single Tell event. Confirmed.
5. This is a golden E2E ticket. Full action registries required. The intended verification layer is the full multi-agent decision pipeline: Agent A detects violation, updates beliefs, then the social pipeline (same or subsequent tick) emits ShareBelief for Agent B.
6. The scenario depends on: (a) SupplyDepleted violation detection, (b) belief update from violation, (c) social candidate generation recognizing the updated belief as relayable, (d) Tell action execution. This is a multi-system emergence chain.
7. Need to verify whether the social pipeline emits ShareBelief based on the violation-updated belief state in the SAME tick as violation detection, or in a subsequent tick after belief refresh. The tick ordering (Perception -> Candidate Generation) means violation detection and social candidate generation both run in the same candidate generation pass. If the belief update from violation detection is visible to social candidate generation in the same pass, the ShareBelief candidate can be emitted in the same tick.

## Architecture Check

## Verification Layers

1. Agent A detects `SupplyDepleted` violation -> decision trace shows violation candidate
2. Agent A's belief store updated with depletion information -> belief store inspection
3. Social candidate pipeline emits `ShareBelief { listener: B, subject: <source> }` -> decision trace shows ShareBelief candidate
4. Agent A executes Tell action to Agent B -> action trace or event log
5. Agent B's belief store updated with the shared information -> belief store inspection
6. Deterministic replay produces identical outcome -> replay companion test
7. Multi-layer golden ticket: violation detection (decision trace) + social candidate generation (decision trace) + Tell execution (action trace) + belief propagation (belief store).

## What to Change

### 1. New golden test in `crates/worldwake-ai/tests/golden_emergent.rs`

Scenario setup:
1. Create world with Place P.
2. Create Agent A at Place P with `PerceptionProfile`, `ViolationDispositionProfile`, `ViolationMemory` (empty), `TellProfile` (so A can share beliefs).
3. Create Agent B at Place P with `PerceptionProfile` (so B can receive Tell).
4. Create a resource source entity S at Place P with commodity C, initial quantity > 0.
5. Seed Agent A's belief store: A believes S has commodity C available at Place P (via prior observation with `last_known_inventory` showing `commodity: C, qty: Quantity(N)` where N > 0).
6. Deplete S's commodity C to quantity 0 via authoritative world mutation — A does NOT observe this directly.

Tick execution:
7. Step ticks. A's perception refresh shows S at P but commodity C depleted (qty 0).
8. Candidate generation detects `SupplyDepleted { commodity: C, source: S, place: P }`.
9. A's beliefs updated to reflect depletion.
10. Social candidate pipeline (`emit_social_candidates`) evaluates A's updated beliefs. Finds new information (supply depletion) that B does not know. Emits `ShareBelief { listener: B, subject: S }`.
11. A may first investigate (if InvestigateMissing is higher priority than ShareBelief) or may Tell first (if ShareBelief is selected). The test should allow sufficient ticks for both behaviors to occur.
12. Eventually A executes Tell to B. B's belief store updated.

Assertions:
- Decision trace (Agent A): `SupplyDepleted` violation candidate generated (or `InvestigateMissing` candidate)
- Decision trace (Agent A): `ShareBelief { listener: B }` candidate generated (may be in same tick or later tick)
- Action trace or event log: Tell action executed from A to B
- Belief store (Agent B): B's beliefs about source S updated to reflect depletion
- Replay companion: deterministic
