# S28-003: Instrument production and enterprise candidates + add `institutional_belief_claims()`

**Status**: PENDING
**Priority**: MEDIUM
**Effort**: Medium
**Engine Changes**: Yes — `GoalBeliefView` gains default method, production/enterprise emitters populate `KnowledgePath`
**Deps**: S28-001, S28-002

## Problem

Production and enterprise candidates generate goals for harvesting, crafting, restocking, and moving cargo. Their knowledge paths must record which entity beliefs provided evidence for resource sources, workstations, sellers, and demand memory entities. Enterprise restocking also requires `MerchantIdentity` self-knowledge. Additionally, the `GoalBeliefView` trait needs `institutional_belief_claims()` for downstream political instrumentation in S28-004.

## Assumption Reassessment (2026-03-25)

1. `emit_produce_goals` at `candidate_generation.rs:963` already calls `emit_candidate_with_trace()` at line 1005. It iterates resource sources and workstations via `view.resource_sources_at()` and `view.workstations_at()`. Provenance for these entities is available via `known_entity_beliefs()` cross-reference.
2. `emit_restock_goals` at line 1018 already calls `emit_candidate_with_trace()` at line 1039. It checks `MerchandiseProfile` and `DemandMemory`. `MerchantIdentity` self-knowledge is straightforward.
3. `emit_move_cargo_goals` at line 1052 uses `emit_candidate()` (NOT `emit_candidate_with_trace()`). Must be upgraded.
4. `GoalBeliefView` trait at `belief_view.rs:27-167` has no `institutional_belief_claims()` method. The method must be added with a default empty-vec return.
5. `PerAgentBeliefView` at `per_agent_belief_view.rs` implements `GoalBeliefView`. It has access to `AgentBeliefStore` which stores `institutional_beliefs: BTreeMap<InstitutionalBeliefKey, Vec<BelievedInstitutionalClaim>>`.
6. `OmniscientBeliefView` does not exist as a named struct — the omniscient view is `PerAgentBeliefView` with omniscient configuration OR a different implementation. Need to verify implementation site.
7. This is an AI diagnostic ticket at the candidate generation layer.

3. No backward-compatibility shims.

## What to Change

### 1. Add `institutional_belief_claims()` default method to `GoalBeliefView`

In `crates/worldwake-sim/src/belief_view.rs`, add to `GoalBeliefView` trait:

```rust
fn institutional_belief_claims(
    &self,
    agent: EntityId,
    key: InstitutionalBeliefKey,
) -> Vec<BelievedInstitutionalClaim> {
    let _ = (agent, key);
    Vec::new()
}
```

### 2. Implement on `PerAgentBeliefView`

In `crates/worldwake-sim/src/per_agent_belief_view.rs`, implement the method by returning claims from the agent's `AgentBeliefStore.institutional_beliefs` for the given key.

### 3. Instrument `emit_produce_goals`

When `ctx.tracing_enabled`:
- For resource sources: construct `BeliefProvenance { subject, aspect: IsResourceSource { commodity }, source, observed_tick }` via `known_entity_beliefs()` cross-reference
- For workstations: construct `BeliefProvenance { subject, aspect: HasWorkstation { tag }, source, observed_tick }`
- Attach to `KnowledgePath.entity_beliefs`

### 4. Instrument `emit_restock_goals`

When `ctx.tracing_enabled`:
- Add `SelfKnowledgeProvenance::MerchantIdentity` to `self_knowledge`
- For seller/demand entities: construct `BeliefProvenance` entries via `known_entity_beliefs()` cross-reference
- Attach to `KnowledgePath`

### 5. Upgrade `emit_move_cargo_goals` to `emit_candidate_with_trace()`

Currently uses `emit_candidate()`. Upgrade to:
- Accept `diagnostics` parameter
- Construct `EvidenceTrace` with cargo lot evidence
- When tracing: populate `entity_beliefs` for cargo lots
- Call `emit_candidate_with_trace()`

### 6. Update call sites

Update the dispatcher that calls `emit_move_cargo_goals` to pass `diagnostics`.
