**Status**: PENDING
**Priority**: HIGH

**Deps**: 002

## Problem

After ticket 002 moves the source files into the new `scenarios/` and `integration/` layout, two cleanup obligations remain:

1. `docs/generated/*` still reflects the pre-T2 source paths and per-file file-stem detail-page names
2. Ticket 001's `golden_inventory.py` still carries dual-layout glob and per-file invocation fallbacks; ticket 001's `test_golden_inventory.py` still carries pre-T2 cargo-output fixtures

Per FND-28, the transitional fallback must not survive the migration as fossilized dead code. Combining doc regeneration and dual-glob retirement in one ticket closes the migration cleanly without leaving a window where the script accepts two layouts but only one exists.

## Architecture Check

1. Combining doc regeneration and dual-glob retirement in one ticket avoids a transient dead-code state: if regeneration landed first and retirement second, there would be a window where `golden_inventory.py` accepts both layouts but the codebase only contains one. Per the spec-to-tickets FND-28-driven combining rule, combining these eliminates a transient dead-branch state in the script.
2. The post-edit grep verification (matches only in docstrings/output strings, never in glob/invocation code paths) is the audit trail that proves the retirement was complete — not just that the doc regen succeeded.

## Verification Layers

1. Generated-doc byte-identity for post-T2 layout → `python3 scripts/golden_inventory.py --write --check-docs` exits 0
2. Dual-glob retirement → `grep -n 'golden_\*\.rs' scripts/golden_inventory.py scripts/test_golden_inventory.py` returns matches only in docstrings or generated-output strings, never in glob/invocation code paths
3. Test-fixture cleanup → `python3 scripts/test_golden_inventory.py` passes with only post-T2 fixtures (the pre-T2 fixtures from ticket 001 are removed; the post-T2 fixtures from ticket 001 remain)
4. Single-layer ticket: tooling cleanup with no engine effects. Action-trace / event-log / decision-trace verification surfaces are not applicable.
